# Declared post-return publication

`run_job.py` accepts an **opt-in** `post_return` version 2 graph-linked implementation contract. Version 2 requires the blocker and held-dependent task IDs from the accepted packet/dependency graph so a terminal reviewer event can be correlated safely; version 1 manifests must be reissued before using this route. The coordinator supplies the accepted packet revision, owned branch and paths, required gates, exact base/repository, current project generation, and independent reviewer route before worker launch. An ordinary manifest without `post_return` keeps the prior behavior. The runner never commits, merges, deploys, or declares acceptance.

## Execution boundary

The default `same_user` mode needs no privileged service or second account. It uses the installed OpenCode headless adapter with `run --pure --format json` and a runner-generated permission map. Shell commands are denied by default; the coordinator declares exact commands or qualified trailing argument prefixes such as `git commit -m *`, `python3 -m unittest *` and `bash infra/local/scripts/ci.sh *`. Git entries must begin with a permitted subcommand; `git *`, Git global options, `bash *`, and wildcards inside command names or paths are rejected. OpenCode 1.18.32 parses shell chains into separate permission resources and denies the call when any command is denied ([shell scanner](https://github.com/anomalyco/opencode/blob/v1.18.32/packages/opencode/src/tool/shell.ts), [permission evaluator](https://github.com/anomalyco/opencode/blob/v1.18.32/packages/opencode/src/permission/index.ts)); the runner checks this exact version before using prefixes. `git status *` also matches bare `git status` in that version. A local installed-CLI probe denied `echo ALLOWED && printf FORBIDDEN > blocked.txt` when `printf *` was denied, and the file was absent. Direct `git push`, `gh`, `curl`, browser/Chrome/Playwright/computer, web search/fetch, external-directory and task tools remain denied. The runner owns `OPENCODE_CONFIG_CONTENT`, so a manifest or inherited config cannot replace that map. It binds canonical `PWD` for every child and injects its own absolute OpenCode `--dir`, because OpenCode 1.18.32 otherwise prefers inherited `PWD` over the subprocess working directory ([run directory selection](https://github.com/anomalyco/opencode/blob/v1.18.32/packages/opencode/src/cli/cmd/run.ts#L333-L345)). Before launch it invokes the selected OpenCode executable's `debug config --pure` with that same `PWD`, verifies every declared permission, and refuses inherited MCP servers or plugins. `--pure` disables external plugins; the separate resolved-config check handles MCP rather than assuming `--pure` does. The pipeline currently starts a fresh session because reused sessions have not been qualified for permission-map persistence. These are mechanical tool restrictions for cooperative workers, **not a security boundary against a hostile same-user process**: an allowed script or code-running test can still publish using same-account credentials, and tool parsing is not a hostile-command sandbox. The supervisor alone performs publication stages, and exact-head, owned-path, clean-tree and gate checks limit mistaken publication. Independent review, CI and human merge authority remain required.

`distinct_uid` remains an optional stronger host mode. A privileged supervisor launches the worker and reviewer under separate unprivileged UIDs with private homes. The worker account must have provider login but no GitHub publication credentials. The runner scrubs coordinator credential/browser environment variables, rejects known GitHub/Git/SSH credential paths in the worker home and checks `gh auth token` under the worker UID. The relay state and attempt roots must be supervisor-owned and mode `0700`, outside the worker checkout/home, with no worker-writable ancestor. State paths are canonicalized before opening or child handoff. These checks require actual host provisioning and do not prove isolation against arbitrary secrets embedded in provider configuration.

Use an owned worktree whose Git control metadata is trusted at launch. The runner records its control digest and refuses publication if `.git`, `config` or `config.worktree` changes. It rejects dangerous local Git config keys, suppresses hooks, fsmonitor, external diff and local credential helpers in publication Git commands, and pushes the exact validated SHA. Each commit in the worker range is checked for paths; merge commits require supervised integration. The declared GitHub URL and `repository` must match; a trusted absolute `gh_executable` is required. HTTPS uses that `gh` executable as the supervisor's Git credential helper. SSH uses the supervisor's batch SSH route. In `distinct_uid` mode the worker's dry-run push must fail with a recognizable permission/authentication error. A transient network error, non-fast-forward, or fake pre-push hook is not proof of denial.

The non-root fixture proves the full local worker return → draft PR → supervised headless reviewer transition with fake provider/GitHub adapters and a bare Git remote. It does not prove real provider-account access, GitHub permission mapping, browser integration state, or hosted CI overlap. Qualify the exact model/effort and routes with a supervised smoke before declaring unattended use. Do not silently substitute another model.

## Contract and run

Start from [post-return-manifest.json](../templates/post-return-manifest.json). Replace every placeholder and bind the worker attempt to the registered project/generation before launch (`relay.py register-project`, `register`, `bind-attempt`). The worker must begin at `start_head` on `branch` with a clean checkout. It writes a compact JSON final to `final_artifact_source` under the worktree; ignore that attempt-specific path in the common Git exclude. The runner copies and hashes it into the private attempt root. A ready final has exact `job`, `attempt`, `packet_revision`, and committed `head`, `result: "ready_for_review"`, and `required_gates` mapping each declared gate to `"passed"`. A known required-gate failure, question, dirty checkout, absent commit, out-of-scope commit, changed Git control metadata or changed head becomes a durable `post-return.json` exception. Existing Markdown finals remain valid for ordinary jobs but cannot authorize this pipeline.

Run `run_job.py --manifest <manifest> --state <private-state.db> --directory <attempt-root>` under a supervised background service. The parent process receipt and callback remain immutable evidence. `post-return.json` records `new`, `pushed`, `pr_created`, `review_started`, `review_verdict_recorded`, or `exception`, including the exact head and PR/reviewer references. `review_started` proves reviewer startup/activity only. For each terminal reviewer run, the supervisor checks the process receipt and artifact digest, requires the final's `reviewed_head` to match the declared head, and queries the live open draft PR to confirm it still names that exact head. It then writes one `review-verdict.json` artifact and emits a deduplicated `kind: "review-verdict"` relay event. The public `relay.py emit` callback rejects this reserved kind; only the verified post-return supervisor path can record it. The event carries `blocking_task_id` and `held_dependent_task_ids` copied from the supervisor-declared packet/graph contract; it contains no executable command or route. An invalid, stale, failed, or unverifiable result is `NOT_ASSESSABLE` with `head_current: false`, never `APPROVED`. A terminal `APPROVED` event may trigger dependency re-evaluation only for graph edges gated by reviewer approval. Edges requiring accepted merge/integration remain held. The event records reviewer evidence; it does not accept the implementation, satisfy CI, authorize merge, or grant reviewer merge rights. Only the designated lead/coordinator may merge after current-head acceptance, passing required CI and cleared operational holds.

The reviewer runner emits the verdict event after its terminal receipt. The monitor can reconstruct that same idempotent event if the runner stops between writing the receipt and emitting it. A retry never reruns the reviewer or worker. For a failed or interrupted publication stage, inspect the lease/process/remote state and then run:

```text
python3 skills/interchange/scripts/post_return.py --manifest <manifest> --state <private-state.db> --directory <attempt-root>
```

This command resumes only the pipeline journal and terminal reviewer recording. It leaves hashed process receipts intact. A lost or uncertain external operation requires inspection before retry; an existing managed-action lease must not be cleared merely because its inspection deadline passed. The monitor exposes exceptions, missing verdict events and undelivered events. The authorized coordinator handles corrections, graph disposition, CI state and all merge/acceptance decisions.

## Reviewer adapter

The reviewer argv is literal and supplied in the manifest. The default same-user route is Claude headless with `--safe-mode --restricted --strict-mcp-config --mcp-config '{"mcpServers":{}}' --tools Read,Glob,Grep --no-chrome`, explicit browser/Chrome/Playwright/computer/MCP and file-mutation tool denies, and `--output-format stream-json`. This route is static review: its tool allowlist excludes shell execution and mutation. Installed CLI controls ignore inherited user/project settings and MCP servers and disable installed customizations, including plugins; the runner rejects overrides, resumed sessions, and a nonempty MCP config. This cooperative same-user route is not hostile-process or prompt-injection isolation.

Claude Bash is available only when the reviewer runs under a distinct UID, using the exact validated `--allowedTools` prefixes for Git read/diff commands, Python unittest, and `dotnet test --no-restore`; the `--disallowedTools` rules deny Git publication, `gh`, direct network clients, browser tools, and mutation tools. Before launch, the supervisor checks the reviewer home for GitHub/Git/SSH credentials, probes that `gh auth token` is unavailable, and requires a denied dry-run push to the owned branch. The isolated UID receives no inherited secret, browser, or Git environment and cannot write the worker-owned checkout. This protects merge authority even if a test process starts another program; it does not claim arbitrary test code is unable to make anonymous network requests. Hosts that cannot provision and verify a distinct UID must keep review static and must not report reviewer-executed test evidence. Codex `exec --sandbox read-only --json` remains available only with `distinct_uid` until its same-user owner-browser integration deny can be verified.

The accepted distinct-UID Claude profile adds only these command rules to the reviewer argv (the checker requires the set to match exactly):

```text
--allowedTools "Bash(git status:*)" "Bash(git diff:*)" "Bash(git show:*)" \
  "Bash(git log:*)" "Bash(python3 -m unittest:*)" \
  "Bash(dotnet test --no-restore:*)"
--tools Bash,Read,Glob,Grep
--disallowedTools "Browser*,Chrome*,Playwright*,Computer*,mcp__*,Edit,Write,NotebookEdit,Bash(gh:*),Bash(git push:*),Bash(git send-pack:*),Bash(curl:*),Bash(wget:*),Bash(ssh:*),Bash(scp:*),Bash(sftp:*),Bash(nc:*),Bash(ncat:*),Bash(telnet:*),Bash(ftp:*),Bash(open:*)"
```

Set `execution_isolation` to a provisioned `{ "mode": "distinct_uid", "uid": <reviewer-uid>, "gid": <reviewer-gid>, "home": <private-home> }` and keep that UID separate from the worker. `--allowedTools` is honored only after runtime credential, checkout-write, and push-denial probes succeed.

Include explicit model and effort flags only after verifying account support. `{head}` and `{pr_url}` in argv are replaced at launch. Require the reviewer to return one JSON object as its final response with `reviewed_head` equal to the PR head and `verdict` equal to `passed` or `changes_needed`; the runner extracts it from the structured event stream. Startup requires actual assistant/tool activity or a valid immediate terminal verdict. PID, empty init, stderr or queue receipt prove no verdict. The journal records requested model/effort and leaves observed values unknown unless independently verified. Review may start while hosted CI runs, but CI and review remain separate acceptance gates.

## Native completion recovery

Native subagents use the same durable activity ledger without fabricating a `run_job` process result. Before dispatch, the coordinator registers and binds the attempt, then declares its next authorized action with `relay.py --state STATE declare-next-action --contract CONTRACT.json`. The contract contains `action_id`, `project`, current `generation`, `source_job`, `source_attempt`, `source_kind: "native-completed"`, trusted literal `recovery_argv`, `cwd`, `deadline_at` and a qualified `recovery_route`. Never obtain executable arguments from a worker return.

The completion adapter records the real final artifact:

```text
python3 relay.py --state STATE emit --job JOB --attempt ATTEMPT --sender SENDER --kind native-completed --artifact FINAL --event-id EVENT
python3 monitor.py --state STATE --project PROJECT --recover
```

The second command must run through an independently scheduled heartbeat or supervisor, not only within the coordinator turn. It atomically claims the declared continuation before launching its adapter. The adapter receives `INTERCHANGE_ACTION_ID`, `INTERCHANGE_PROJECT`, `INTERCHANGE_OWNERSHIP_GENERATION`, `INTERCHANGE_SOURCE_EVENT_ID`, `INTERCHANGE_CLAIM_TOKEN` and `INTERCHANGE_RELAY_STATE`. After actual coordinator wake, it records `relay.py --state STATE recovery-awake`; after verified reviewer startup it records `relay.py --state STATE action-started --evidence-path PATH --evidence-sha256 SHA256`. Identity and claim arguments default from those environment variables. Inspect `relay.py --state STATE next-action --action-id ID`: `acceptance_met` requires the next action to have started within both the configured deadline and maximum latency. Launching the adapter or recording a queued event is insufficient.

The action-start proof file names `kind: "reviewer_started"`, the action ID, ownership generation, and exact `reviewer_job` and `reviewer_attempt`. The reviewer attempt must be registered, project-bound to that generation and launched after coordinator wake. Its supervised stdout must contain structured assistant/tool activity, or its terminal receipt and final verdict must prove a validated review of the declared head. A live PID, a launch row, and unstructured output such as `sleeping` cannot mark the action started. Supply `expected_head` in the declared action when a commit head is part of the review contract.

After takeover, an unclaimed action remains at its old generation until the new owner explicitly adopts it. Write a fresh qualified route proof for the current coordinator and generation, then call `relay.py --state STATE adopt-next-action --contract ADOPTION.json`. That contract contains `action_id`, `expected_generation`, `generation`, and `recovery_route`. Adoption preserves the original action ID, source completion, deadline and latency allowance, records the previous generation in `next_action_history`, and lets the scheduled monitor claim the action once. If the accepted work is explicitly withdrawn, use `dispose-next-action --contract DISPOSITION.json` with the same fields plus a concrete `reason`; this records a stopped disposition and cannot claim completion. A claimed, delivered or awake action cannot be adopted or disposed until its process and side effects are reconciled. Old-generation actors remain fenced.

The recovery route identifies an independently scheduled host route, current coordinator and generation, qualification/expiry times, maximum latency and a hashed local proof file. Its idle qualification must show ordered worker completion, queue, delivery, coordinator wake and actual next-action startup. `validate_recovery_route` in `relay.py` is the shared validator used by the scheduling gate. An expired or absent proof cannot justify unattended yielding. There is no generic promise that a local script can wake every client: qualify the installed host adapter separately.

The regression runs worker completion in a separate process while the coordinator is absent, races two scheduled monitor processes, and verifies exactly one reviewer launch. This proves ledger and adapter mechanics, not live Codex/Claude wake availability. An ambiguous interrupted claim remains for supervised reconciliation rather than blind relaunch.


## Live same-user qualification (24 September 2026)

OpenCode 1.18.32, requested `opencode-go/deepseek-v4.1-flash` / high, completed a real bounded Omni CI-script correction at `24ce190c9aa6b191dc72fdf6dc161377cb65c495`. It read and edited the declared checkout, ran seven regression tests and the real runner-routing gate, redirected logs, captured exit status, and made its own commit with a task-derived message. The regression executes the actual CI script with a stub toolchain; this is not a full .NET/Docker application gate.

Without a further coordinator publication or review-dispatch turn, the supervisor pushed the owned branch, created [draft Omni PR #750](https://github.com/marvinamiranda/omni237/pull/750), and launched the restricted Claude reviewer while [hosted CI](https://github.com/marvinamiranda/omni237/actions/runs/35978717368) ran. Actual reviewer file reads and exact-head diff inspection were observed; its test commands were denied, so its review is static, not independent executed-test evidence. Re-running the post-return stage reused the same PR and reviewer attempt.

The first trial was stopped without publication after discovering OpenCode preferred inherited `PWD` to the subprocess cwd. The runner now binds both `PWD` and its own `--dir`; the successful second attempt used the correct checkout. The live run also confirmed that reviewer prose around JSON needs a strictly bounded collector rather than assuming prompt formatting is enforced.

This qualifies the tested same-user coding/publication/reviewer-start route, not a hostile-worker sandbox, full application acceptance, or an idle coordinator wake route. The trial PR remains a draft for its own acceptance and human merge decision.
